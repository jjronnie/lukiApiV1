Database

Database schema overview.

Tables

TablePurpose
usersCustomer & provider accounts
ordersService bookings
servicesService catalog
service_categoriesService categories
walletsProvider wallets
provider_profilesProvider details
order_offersProvider offers
notification_recordsIn-app notifications
audit_logsActivity tracking

Key Relationships

  • User → Order: user_id (one-to-many)
  • User → Wallet: user_id (one-to-one)
  • User → ProviderProfile: user_id (one-to-one)
  • Order → Service: service_id (many-to-one)
  • Order → User: user_id (belongsTo)
  • Order → ProviderProfile: provider_profile_id (belongsTo)
  • ServiceCategory → Service: service_category_id (one-to-many)

Development Tips

  • All amounts stored in UGX cents (divide by 100 for display)
  • Phone numbers stored in E.164 format (+256...)
  • Timestamps in UTC, displayed in Africa/Kampala timezone
  • Use HasPublicId trait for public_id generation
